# AGENTS.md

Mika: a VTuber AI companion for games, code and nerd culture. Runs locally on the user's PC (Windows, Linux and macOS). Product text is in pt-BR.

## Stack
- Tauri 2 (Rust backend in `apps/desktop/src-tauri`), Node 24, pnpm 10 (`packageManager`)
- Renderer: React 19, Tailwind 4, TypeScript 7; lint and formatting with Biome 2
- Tests: Vitest 5 (unit and contract), Playwright 1.64 (E2E)
- Electron was removed in the Tauri migration (2026-09-22). Do not reintroduce it
- The renderer is UI only, plus the bridge in `apps/desktop/src/renderer/bridge`; backend logic lives in Rust

## Commands
| Command | What it does |
|---|---|
| `pnpm lint` | Biome (`biome check .`) |
| `pnpm typecheck` | Types across all workspaces |
| `pnpm gates` | Invariant gates in `scripts/checks/` + `test:rust` |
| `pnpm test:rust` | `cargo test --lib` for the Tauri shell |
| `pnpm test:unit` | Vitest with a coverage ratchet (`thresholds` in `vitest.config.mts`, only goes up) |
| `pnpm build` | Prompts and renderer (`vite.tauri.config.ts`) |
| `pnpm --filter @mika/desktop tauri:build` | Native installer |
| `pnpm test` | Full E2E suite (`apps/desktop/e2e`); only when the user asks |
| `pnpm dev` | `tauri dev` |
| `pnpm live2d:gen` | Regenerates the avatar motions |

Run commands in quiet mode (`--quiet`, `--silent`) to save tokens.

## Structure
- `apps/desktop/src-tauri/src/modules/<ctx>/`: Rust backend. Core: `brain`, `browser`, `chat`, `inference`, `llm`, `memory`, `telemetry`, `voice`, `vision`. Own contexts: `gamer/`, `mcp/`. Late features: `features/<ctx>/`, registered in `features/mod.rs` (a folder without a `mod` line is a compile error)
- `apps/desktop/src/features/<ctx>/renderer/`: each feature's UI, registered in `apps/desktop/src/renderer/src/lib/feature-ui-registry.ts`
- `apps/desktop/prompts/<ns>/*.md`: markdown prompts, outside `src/`
- `apps/desktop/e2e/`: E2E specs, fixtures and screenshots
- `packages/sdk/`, `packages/sdk-ui/`: contracts, types, i18n and shared UI
- `scripts/checks/`: invariant gates; `specs/`: specifications
- `.claude/skills/test-audit/`: test rules and pruning flow

## Conventions
- Architecture invariants
  - The renderer does not import Node (`fs`, `path`). It talks to the backend only through `window.electronAPI`, the bridge in `apps/desktop/src/renderer/bridge/`
  - Typed channels and routes live in `packages/sdk/src/contracts/desktop-ipc.ts`. Sensitive routes call `assertOwnerSurface` (Rust)
  - Modules communicate only through typed events: Rust bus in `apps/desktop/src-tauri/src/events/`, keys mirrored in `packages/sdk/src/svc/events.ts`. No DI container in TypeScript
  - The Rust backend never reads TypeScript at runtime, except `include_str!`/`include_bytes!` of shared source data (`check:rust-include-paths`)
  - STT (Whisper) and TTS (Supertonic/Kokoro) run in Rust (`modules/inference/`). The backend accepts only PCM16 mono 16 kHz; audio decoding happens in the renderer
  - Local LLM default: Ollama. Remote providers are resolved in Rust (`modules/llm.rs`, `modules/brain/`). The model catalog is in `packages/sdk/src/llm/`
  - Every line Mika speaks is generated by an LLM
- Naming
  - Kebab-case file names, with dotted suffixes (`.service.ts`, `.runtime.ts`, `.schema.ts`, `.feature.ts`, `.module.ts`), never hyphens (`chat-service.ts` is wrong)
  - PascalCase only for React components. Never `index.<something>.ts`; `index` is the barrel
  - `prompt-loader.ts` in each module does not move: it resolves the prompt folder from its own directory, and moving it makes prompts disappear with no error
- Product rules
  - Zero mocks or fake data in production code. Every feature and integration is real end to end
  - Zero dead buttons: every UI control drives real runtime behavior
  - Every backend capability has a visible or configurable UI for the user
  - Support Windows, Linux and macOS. Screen capture, processes and shortcuts must not assume one OS
  - Mika is proactive and sensory: listens (STT), watches the screen (Vision), talks (LLM), and starts conversations with a cooldown
  - Simplicity: functions of 10 to 20 lines, cognitive complexity <= 15 (Biome), no indirection that only forwards calls
  - UI reference: the `character` and `user` screens. Hero at the top, `GlassSection`, `BentoGrid` with `GlassCard`, `uppercase tracking-[0.12em]` headers, `SectionDivider`
  - Controls only via `@mika/sdk-ui/settings` (`AuroraField`, `GlassSelect`, `GlassSlider`, `GlassToggle`, `StatusPill`, `StatTile`), with semantic color tokens and no literal colors

## Testing
- Test first. For a bug, write the failing test that reproduces it, then fix. A unit test written after the code only to cover lines or raise `thresholds` is rejected
- E2E is the valid proof for UI and for the real app. Unit and contract tests (Vitest) are for pure logic
- Every E2E spec ends with a deterministic, repeatable artifact: a PNG in `apps/desktop/e2e/screenshots/` and/or a JSON with the asserted state. A trace or video that exists only on failure does not count
- Low-signal tests get deleted. Load the `test-audit` skill before writing, reviewing or deleting tests
- Never lower coverage `thresholds` or disable a gate to make checks pass
- If a test starts failing after a fix, the first hypothesis is that the test documented the defect. Read the test before reverting the fix
- Gates: each invariant comes with a gate, or with a reason it cannot be automated. A script that no step runs is not a gate

## Validation workflow
In this order. If one fails, stop:
1. `pnpm lint`
2. `pnpm gates`
3. `pnpm typecheck`
4. Unit tests only for the touched files: `vitest run <path>` and `cargo test --lib -- <filter>`. The full suite only when the user asks
5. `pnpm build`
6. E2E only when the user asks, and only the requested specs: `playwright test -c e2e/playwright.config.ts e2e/specs/<spec>.spec.ts`, after `pnpm --filter @mika/desktop build:e2e`
7. With E2E run and UI changed, open the screenshots in `apps/desktop/e2e/screenshots/`. A green gate does not prove the screen

Never declare work done with something failing. A failure caused by something outside the change is reported, not hidden.
